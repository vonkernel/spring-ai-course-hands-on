# 04. 코드 리뷰

IDE 의 코딩 에이전트에 빈 구현을 맡길 때 **무엇을 전달하고 무엇을 확인할지**를 정리했습니다.

코딩 에이전트에 이 파일을 함께 전달하고 「이 기준으로 검토해 달라」고 요청할 수 있습니다.

---

## 코딩 에이전트

| 전달할 것 | 어디에 있나 |
| --- | --- |
| **인터페이스와 Javadoc** | 구현할 클래스가 구현하는 인터페이스. 예: `ai/ArticleBodyExtractor.java` |
| **입출력과 확인 방법** | [03. 구현](03-구현.md) 의 해당 카드 |
| **완성본 경로 목록** | 이 문서의 「수정하지 않는 곳」 |

**코딩 에이전트가 모르는 것이 있습니다.** 이 계약을 택한 이유와 어떤 함정이 있는지입니다.
그것은 [03. 구현](03-구현.md) 의 **주의 사항**과 Javadoc 에 적혀 있으므로 함께 전달하거나
직접 확인합니다.

---

## 리뷰 기준

생성된 코드를 아래 다섯으로 검토합니다.

| # | 기준 | 확인 방법 |
| :-: | --- | --- |
| 1 | **완성본 수정 없음** | `git status` 로 변경된 파일이 빈 구현뿐인지 |
| 2 | **계층 규칙 준수** | `./gradlew test` 의 `LayeringTest` |
| 3 | **계약대로 반환** | `./gradlew playground --tests '*<클래스>CheckTest'` |
| 4 | **예외 무시 없음** | 코드를 직접 읽는다 |
| 5 | **`./gradlew test` 통과** | 전체 실행 |

### 1. 완성본 수정 없음

빈 구현은 일곱 곳에만 있습니다.

```
ai/shell/                 LLM · Moderation 호출 8개
search/plan/              벡터 검색 계획 2개 (BodyVectorPlan · SummaryVectorPlan)
search/shell/             검색 서비스
service/chat/RelevancePostProcessorShell   근거 후처리
service/chat/StoryTools   모델이 호출하는 스토리 도구 3종
service/chat/TopicTools   모델이 호출하는 주제(기술 분야) 도구 4종
service/chat/RagChatServiceShell      Q&A 1단계
service/chat/AgentChatServiceShell    Q&A 2단계
service/chat/MemoryChatServiceShell   Q&A 3단계
```

**수정하지 않는 곳**

```
domain/  persistence/  web/  adapter/  config/
service/*/model/  service/*/port/
service/topic/DefaultTopicService   service/setup/AnalysisMapper
service/chat/ChatTurn   service/chat/SearchEvidence   service/chat/SearchRecord   service/chat/EvidenceDocuments
service/setup/PipelineSetupService   service/setup/StageTracker   service/setup/PipelinePolicy
service/setup/StoryExtractor   service/setup/StoryTransformer   service/setup/StoryLoader
service/setup/DefaultStoryProcessor
ai/*.java (shell/ 제외)   search/*.java (shell/ 제외)
search/plan/KeywordArrayPlan   search/plan/FullTextPlan
init/*.sql  frontend/  src/main/resources/static/
src/test/ (단, src/test/java/hn/chatbot/playground/ 는 예외)
```

코딩 에이전트는 막히면 완성본을 고쳐서 해결하려 듭니다. 대개는 빈 구현 쪽에서 풀 수 있는
문제입니다.

### 2. 계층 규칙 준수

**안쪽 계층은 바깥쪽 계층을 모릅니다.** 자세한 것은 [02. 전체 구조](02-전체-구조.md) 의
「계층」에 있습니다.

- `ai/` 와 `search/` 는 아무것도 참조하지 않습니다. 필요한 것은 인자로 받습니다
- `service/` 는 `web/` 도 `persistence/` 도 `adapter/` 도 모릅니다. 포트로만 만납니다

`LayeringTest` 가 자동으로 잡습니다.

### 3. 계약대로 반환

Javadoc 이 정한 반환 계약을 지키는지 봅니다. 특히 **값이 없을 때**입니다.

- 빈 결과를 예외로 만들지 않았는지. 찾지 못하는 것이 정상 경로인 구현이 있습니다
- 구조화 출력이 준 빈 문자열을 그대로 넘기지 않았는지

### 4. 예외 무시 없음

`catch` 로 잡고 아무것도 하지 않거나, 기본값을 지어내 돌려주는 코드가 있는지 봅니다.
실패가 묻히면 결과가 비어 있는 것과 구분되지 않습니다.

### 5. `./gradlew test` 통과

```bash
./gradlew test
```

키 없이 전부 통과해야 합니다. 빈 구현은 `./gradlew playground` 의 확인 테스트가 잡습니다.

---

## 사람만 볼 수 있는 것

계층 규칙과 반환 계약은 테스트가 잡습니다. **프롬프트가 제대로 쓰였는지는 테스트가
판정하지 않습니다.**

- 규칙은 `system`, 이번 입력은 `user` 로 나뉘어 있는지
- 값 목록이 필요한 구현에서 목록이 프롬프트에 들어 있는지
- 찾지 못했을 때의 규칙이 프롬프트에 있는지

`./gradlew playground --tests '*<클래스>CheckTest'` 가 출력하는 결과를 눈으로 확인합니다.
