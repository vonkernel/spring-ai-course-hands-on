# 01. 시작하기

애플리케이션을 기동하고, **기동 직후의 상태가 정상임**을 확인하는 것이 목표입니다.

---

## API 키 설정 위치

같은 OpenAI 키를 두 곳에 각각 넣습니다.

| 사용 주체 | 설정 위치 |
| --- | --- |
| **애플리케이션** (분석 · 임베딩 · 검열) | 저장소 루트의 `.env` |
| **IDE 의 코딩 도구** (Codex) | JetBrains AI 설정 |

한쪽에 넣은 키를 다른 쪽이 읽지 않습니다. `.env` 에만 넣으면 IDE 가, IDE 에만 넣으면
애플리케이션이 동작하지 않습니다.

### 애플리케이션용 OpenAI 키

저장소 루트에서 `.env.example` 을 `.env` 로 복사하고 키를 채웁니다.

```
:: Windows
copy .env.example .env
```

```bash
# macOS / Linux
cp .env.example .env
```

```
OPENAI_API_KEY=sk-...
```

애플리케이션과 테스트가 모두 이 파일을 읽습니다. 운영체제와 터미널 종류에 상관없이
동작하고, 고친 뒤 다시 실행하면 바로 반영됩니다.

- **값에 따옴표를 붙이지 마세요.** `OPENAI_API_KEY="sk-..."` 로 적으면 따옴표까지
  키로 읽혀 인증에 실패합니다
- **같은 이름의 환경 변수가 이미 있으면 그쪽이 우선합니다.** 예전에 `setx` 등으로
  `OPENAI_API_KEY` 를 설정해 둔 적이 있다면, `.env` 를 고쳐도 반영되지 않습니다

**`application.yml` 에 키를 넣지 마세요.** 이 저장소는 공개돼 있습니다.
`.env` 는 커밋되지 않습니다.

### IDE 코딩 도구 설정

JetBrains AI 설정에서 3rd party 제공자로 OpenAI 를 연결하고, 위에서 쓴 OpenAI 키를 넣은 뒤
Codex 를 고릅니다. 메뉴 이름은 IDE 버전에 따라 조금씩 다릅니다.

**연결 여부는 AI 채팅에 질문을 한 줄 입력해 확인합니다.** 답변이 오면 연결된 것입니다.

## 준비물 확인

터미널에서 아래 두 명령으로 확인합니다. 키가 제대로 읽히는지는 「연결 확인」 절에서 확인합니다.

```bash
java -version          # 17
docker --version       # 설치 여부 확인
```

**Node 는 필요 없습니다.** 프론트엔드 빌드 산출물이 저장소에 들어 있습니다.

## 기동

```bash
docker compose up -d     # PostgreSQL + pgAdmin
./gradlew bootRun        # 애플리케이션
```

- 애플리케이션 → http://localhost:8080
- pgAdmin → http://localhost:5050 (`admin@local.dev` / `admin`)

`docker compose up -d` 는 처음 실행될 때 `init/*.sql` 로 테이블을 만듭니다.

---

## pgAdmin 서버 등록

pgAdmin 에는 서버가 등록되어 있지 않습니다. 처음 한 번 직접 추가합니다.

1. `http://localhost:5050` 에 접속합니다. 로그인 화면 없이 바로 들어갑니다.
2. 왼쪽 **Servers** 를 우클릭해 **Register → Server...** 를 고릅니다.
3. **General** 탭의 Name 에 아무 이름이나 적습니다. 예: `hnanalyzer`
4. **Connection** 탭을 아래처럼 채우고 **Save** 를 누릅니다.

| 항목 | 값 |
| --- | --- |
| Host name/address | `db` |
| Port | `5432` |
| Maintenance database | `hnanalyzer` |
| Username | `hn` |
| Password | `hn` |

> **Host 에 `localhost` 를 넣으면 붙지 않습니다.** pgAdmin 도 컨테이너 안에서 돕니다.
> 거기서 `localhost` 는 pgAdmin 자기 자신이라 PostgreSQL 이 없습니다. 두 컨테이너가
> 같은 네트워크에 있으므로 `docker-compose.yml` 의 서비스 이름인 `db` 로 찾아갑니다.
> `localhost:5432` 는 IntelliJ 나 `psql` 처럼 **노트북에서 직접 붙을 때** 쓰는 주소입니다.

등록하면 `hnanalyzer → Schemas → public → Tables` 에 `story` · `comment` · `article` ·
`analysis` · `body_chunk` 와 벡터 스토어 두 개가 보입니다.

## 빈 구현 상태의 동작

애플리케이션을 기동하면 아래 상태가 보입니다. **모두 의도된 동작입니다.**

### 데이터 셋업의 시연 진행

진행바가 움직이고 8개 단계에 차례로 체크 표시가 붙고 로그가 출력되지만, 분석까지 가지는
않습니다. 파이프라인이 부르는 부품(본문 추출 · 분석 · 청킹 · 적재 등)이 비어 있으면 실행 뼈대가
**진행 화면만 시연**합니다. 로그 첫 줄에 그 사실이 표시됩니다.

파이프라인 연결은 완성본입니다. 파이프라인이 부르는 부품을 채우는 것이 실습입니다.

### 주제 탐색 탭의 잠금

"셋업이 실행됐지만 적재된 스토리가 0건입니다" 라는 문구가 표시됩니다. 셋업은 실행됐지만
저장된 데이터가 없으므로 문구 그대로의 상태입니다. **잠금 여부는 적재된 스토리 수만으로
판정**하므로, 분석 결과가 한 건이라도 생기면 바로 해제됩니다.

### Q&A 탭의 스트리밍 응답

무엇을 물어도 "아직 구현되지 않았습니다…" 가 **글자 하나씩** 흘러나옵니다.

잠그지 않은 이유가 있습니다. 글자가 하나씩 채워진다는 것은 서버에서 브라우저까지
스트리밍 경로가 **처음부터 연결돼 있다**는 뜻입니다. 이후 답변 생성을 구현하면
실제 답변이 같은 경로로 출력됩니다.

### 초기 테스트 결과

```bash
./gradlew test
```

전부 통과해야 합니다. 실패하는 테스트가 있으면 환경 문제입니다.
Docker 컨테이너가 실행 중인지 확인해 주세요. 키는 이 단계에서 필요하지 않습니다.

## 연결 확인

키 설정 여부는 아래 명령으로 확인합니다.

```bash
./gradlew playground --tests '*FirstCallTest'
```

모델 호출 · 임베딩 · 벡터 검색을 차례로 한 번씩 하고 결과를 출력합니다.
**구현할 코드는 없고 실행만 하면 됩니다.** 통과하면 환경이 준비된 것이고,
실패하면 키나 Docker 문제이지 구현 문제가 아닙니다.

`playground` 는 `./gradlew test` 에서 제외돼 있습니다. 키가 필요한 테스트라
함께 실행하면 「키 없이 전부 통과한다」는 기준이 흐려지기 때문입니다.
